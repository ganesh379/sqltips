Why does PostgreSQL create multiple processes? Here is the process map of a real server.

PostgreSQL uses a "process per user" model. The postmaster is the supervisor process: it listens for connections and spawns one backend process per client. All processes cooperate through shared memory and semaphores.

Not every process exists on every server. The autovacuum launcher needs autovacuum = on (the default). On our test server the archiver appeared only after archive_mode = on and a restart. Streaming replication adds a walsender on the primary and a walreceiver on the standby. Parallel workers come from max_worker_processes (default 8).

PostgreSQL DBA tip: check SELECT pid, backend_type FROM pg_stat_activity; and end a stuck session with pg_terminate_backend(pid), not kill -9. On a test server, kill -9 on one backend made the postmaster log "terminating any other active server processes" and run crash recovery.
